## HOT FIX (2026-10-07): loopback-only socket and audited dispatch

Committed with no issue link, by the user's decision (2026-10-07), as
`HOT FIX - Revit socket bound to loopback only and every command routed through the audit log.`
The work was implemented and verified on 2026-10-06, restored after the 2026-10-07 sync, and
re-verified.

### What changes

- `plugin/Core/SocketService.cs`: the listener binds `SocketService.BindAddress = IPAddress.Loopback`
  (127.0.0.1) instead of `IPAddress.Any`. `ProcessJsonRPCRequest` keeps JSON parsing and validation
  and dispatches with `_commandExecutor.ExecuteCommand(request)` instead of calling
  `command.Execute` itself.
- `server/src/utils/ConnectionManager.ts`: exports `REVIT_HOST = "127.0.0.1"` and `REVIT_PORT = 8080`
  and connects to them instead of `"localhost"`.
- `server/tests/utils/connection.test.ts` (new) and `server/tests/TESTS.md`: the pinned-host test, plus
  a round trip against a fake listener bound only to `127.0.0.1:8080` (skipped if 8080 is busy).
- Wiki: decisions [0021](../../decisions/0021-loopback-only-socket.md) and
  [0022](../../decisions/0022-local-shared-secret-handshake.md), and updates to 0013, 0014, the plugin,
  server, tests, threading, four-part pattern, audit-trails, doc-drift and build-and-deploy pages.

### Decisions and reasons

- **Bind loopback only** (security). The upstream `IPAddress.Any` bind let any machine on the network
  drive Revit while CEM_RevitAI was on, including `send_code_to_revit` (arbitrary C#): remote code
  execution with no authentication. → [0021](../../decisions/0021-loopback-only-socket.md)
- **Pin the client to 127.0.0.1 rather than dual-binding v4+v6.** `localhost` resolves in OS order
  (often `::1` first) and reaches an IPv4-only listener only through Node 20+'s fallback. Both ends
  are ours, so one IPv4 listener plus an explicit host is deterministic on every Node version.
  *Rejected:* a second `::1` listener (more code, and it only helps foreign clients).
- **Route dispatch through `CommandExecutor`** (bug fix). Upstream's `SocketService` executed
  commands directly, so the Cemengal `ActionLogger` audit log was never written. Now every command
  is audited. Together with [0023](../../decisions/0023-send-code-scripts-not-persisted.md), script
  bodies are still not logged (`"<omitted>"`). Side effect: `CommandExecutionException` error codes
  and data are preserved in the JSON-RPC error.
- **Shared-secret handshake: proposed only** ([0022](../../decisions/0022-local-shared-secret-handshake.md)).
  The residual exposure is other local users on shared or RDS machines. The coordinator asked for it
  to be recorded, not built.
- **No C# unit test.** The TUnit suite runs only inside live Revit and references neither the plugin
  nor the command set. Verified by build plus the TS tests. **Live check still pending** (Revit was
  not running): `netstat -ano | findstr :8080` should show `127.0.0.1:8080`, and a call should add a
  `Log\actions_<date>.jsonl` line.
- **Build environment note:** the PATH `dotnet` is SDK 5.0.103, which can't compile `CEM_RevitAuth`.
  Build with `%LOCALAPPDATA%\Cemengal\dotnet` ([build and deploy](../../workflows/build-and-deploy.md)).

Verification on 2026-10-07: `npx vitest run` 34/34; `npm run build` clean; plugin Debug R24 builds
with 0 warnings. Ship it by rebuilding and redeploying CEM_RibbonUI with Revit closed.
