# Commits 2026-11 (Cemengal: cem-revit-ai declared in .mcp.json)

## 2026-11-03: `cem-revit-ai` declared in `.mcp.json`

Asked by the user: update `.mcp.json` in the repos whose MCP servers are not what is needed to develop code.
Committed with no issue link, by the user's decision for this change ("commit that little changes without a issue
link"), as `FIX - Declare cem-revit-ai in .mcp.json.` The rule that a commit waits for the issue URL is unchanged.
Reviews were skipped by the user's decision.

### What changes

- `.mcp.json`: adds `cem-revit-ai`, next to the unchanged `qmd` entry:
  `{ "type": "stdio", "command": "node", "args": ["${CEM_REVITMCP_SERVER:-server/build/index.js}"] }`.
- [Smoke test](../../workflows/smoke-test.md) and [build and deploy](../../workflows/build-and-deploy.md): a Claude Code
  session in this repo gets the server from that entry. `server/build/` is gitignored, so a fresh checkout still needs
  `npm install` and `npm run build` in `server/`.

### Decisions and reasons

- **The entry is project-level, with a relative path and no machine value**, so it works from any checkout location.
  Claude Code starts a project server with the project as its working directory. `CEM_REVITMCP_SERVER` can still
  point it at another build.
- **It goes in the tracked settings file where one lists enabled servers.** None does here:
  `.claude/settings.json` has no `enabledMcpjsonServers`, and `.claude/settings.local.json` does not exist, so neither
  file changed.
- *Rejected:* an absolute or drive-letter path, because it breaks on any other checkout.
- *Rejected:* a user-level registration only, because it does not reach other machines.

### Verification

An `initialize` and `tools/list` run from the repo root on 2026-11-03: `cem-revit-ai` answered with 125 tools from the
default path, with `CEM_REVITMCP_SERVER` unset. That proves the server starts and lists its tools. It does not prove
that Revit is reachable: no Revit was opened for this change.
